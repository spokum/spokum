# СпокУм — как всё запустить

Пошагово. Делай сверху вниз, ничего не пропуская. Занимает минут пятнадцать.

## Что получится

| Часть | Где живёт | Что делает |
|---|---|---|
| Сайт | GitHub Pages | лента, чаты, игры, настройки, профиль, панели админа и модератора |
| База и вход | Supabase | аккаунты, пароли, посты, сообщения, жалобы, наказания |

Сайт статический, база отдельно. Поэтому соцсеть общая: любой человек заходит по ссылке, регистрируется и видит тех же людей и те же посты, что и ты.

## Текущая архитектура

| Часть | Где работает |
|---|---|
| Сайт | GitHub Pages, статические файлы из `web/` |
| API, Auth, REST и Storage | Собственный Supabase в Docker на VDS, внешний адрес `https://api.spokum.ru` |
| Конфигурация Supabase | `/opt/spokum/supabase` на VDS |
| Android | WebView с интерфейсом из встроенных assets; использует ту же базу |
| Desktop | Electron с тем же web-интерфейсом |
| Серверная ИИ-модерация | Supabase Edge Function `moderate`; ключ провайдера хранится только в env на VDS |

Фронтенд подключается через `web/js/backend/remote-db.js`. Каталог `server/` — старый неиспользуемый вариант на Node + SQLite, не часть production.

## Схема базы и изменения

`supabase/schema.sql` — полный снимок production-схемы на момент фиксации в Git. Он нужен для новой пустой установки. Это **не idempotentный скрипт**: не запускай его повторно на работающей базе.

После восстановления baseline на новой пустой установке также примени все миграции. Для существующего production применяй только ещё не установленные файлы из `supabase/migrations/` в порядке имён. Перед применением сделай резервную копию, затем передай миграцию в `psql`:

```bash
cd /opt/spokum/supabase
docker compose exec -T db psql -v ON_ERROR_STOP=1 -U postgres -d postgres < /путь/к/миграции.sql
```

Применяй каждую миграцию один раз и сначала проверяй её на восстановленной копии базы. После изменения схемы обнови снимок `schema.sql` отдельно, чтобы он не расходился с production.

## Резервные копии

`infra/backup-spokum.sh` создаёт полный `pg_dump` базы и архив Storage, проверяет их читаемость и записывает SHA-256. Таймер запускает копирование ежедневно; копии `daily-*` хранятся 14 дней, ручные `pre-fixes-*` не удаляются.

Установка или обновление на VDS из корня репозитория:

```bash
install -D -m 700 infra/backup-spokum.sh /opt/spokum/bin/backup-spokum.sh
install -m 644 infra/spokum-backup.service /etc/systemd/system/spokum-backup.service
install -m 644 infra/spokum-backup.timer /etc/systemd/system/spokum-backup.timer
systemctl daemon-reload
systemctl enable --now spokum-backup.timer
systemctl start spokum-backup.service
systemctl status spokum-backup.service --no-pager
systemctl list-timers spokum-backup.timer --no-pager
```

Копии лежат в `/opt/spokum/backups/daily-<timestamp>`. Пока они хранятся только на том же VDS: при потере всего диска или сервера они пропадут вместе с production. Для защиты от такого сценария нужна отдельная внешняя копия.

Для проверки восстановления используй пустую базу, не production:

```bash
cd /opt/spokum/supabase
docker compose exec -T db createdb -U supabase_admin spokum_restore
docker compose cp /opt/spokum/backups/daily-<timestamp>/spokum-db.dump db:/tmp/spokum-restore.dump
docker compose exec -T db pg_restore -U supabase_admin -d spokum_restore --no-owner --no-comments --exit-on-error /tmp/spokum-restore.dump
docker compose exec -T db rm -f /tmp/spokum-restore.dump
```

Архив Storage распаковывают только в отдельный пустой каталог после остановки записи файлов. Не распаковывай его поверх работающего хранилища без плана отката.

## Публичные и серверные ключи

В `web/config.js` находятся публичный URL и `anon` ключ. Они доступны браузеру, а права ограничиваются RLS и серверными функциями. `service_role`, пароль базы, GitHub token и `AI_API_KEY` нельзя добавлять в `web/`, Git или сообщения.

ИИ-модерация после миграции выключена. Включать её может только администратор. Когда она включена, старые клиенты без поддержки одноразовых токенов не смогут отправлять текст — сначала опубликуй сайт и новую сборку Android.

## GitHub Pages и приложения

Пуш в ветку `Main` запускает workflow `Publish site`, который обновляет ветку `gh-pages`, и workflow `Build APK`. Готовые файлы появляются в GitHub Releases с тегом `apk`.

Сайт обновляется после публикации `gh-pages`. Android **не скачивает интерфейс с сайта автоматически**: изменения `web/` попадают в приложение только в новой APK/AAB, которую пользователь должен установить.

## Администратор

Аккаунт с юзернеймом `vanya8` получает права администратора на уровне схемы. В существующем production права уже настроены; для новой установки зарегистрируй этот аккаунт первым, пока имя свободно.

## Как этим пользоваться

### Разделы снизу
- **Лента** — посты с фото и тегом настроения, фильтр по настроению, лайки, комментарии, жалобы.
- **Чаты** — поиск людей по юзернейму и словам, личные диалоги, группы, каналы, фото, голосовые, эмодзи, звонок, контакты.
- **Игры** — Орбита (стрелялка), Дрифт (платформер), Пульс, Эхо, Поток. Есть рекорды и таблица лидеров.
- **Настройки** — темы, акценты, интерфейс, смена пароля, сессии.
- **Профиль** — аватар, имя, био, настроение, лайки, записи, вход в панели.

### Тихие комнаты

У каждого тяжёлого настроения своя комната. Выбрали настроение в профиле — она открывается сама; выбрали тег у поста — появляется мягкое предложение зайти. В любой комнате уведомления выключены, лента и чаты ждут, сверху идёт таймер.

| Настроение | Комната | Что внутри |
|---|---|---|
| Тревога | Тихая комната | дыхание 4-7-8, опора 5-4-3-2-1, звуки, слова, пузыри |
| Грусть | Тёплый угол | тёплые слова, маленькие шаги, письмо себе, звуки, мягкое дыхание |
| Злость | Комната выдоха | длинный выдох, сжать-отпустить, разряд по шарам, слова, звуки |
| Усталость | Место отдыха | пауза на две минуты, ровное дыхание, звуки, слова, шаги |

Зайти вручную — в профиле кнопка **Тихие комнаты**.

### Дневник настроения

Раз в день, начиная с утра, приложение предлагает записать три-пять предложений о своём состоянии. Записи приватные: их не видит никто, включая админов, — база отдаёт их только автору.

Там же можно выбрать **слово дня** и решить, показывать ли его в профиле рядом с ником. Слово держится сутки с небольшим.

Профиль → **Дневник**: сводка за период (какое настроение чаще, в какие дни недели тяжелее, стало легче или тяжелее, сколько дней подряд), облако слов за месяц — частые слова крупнее — и все записи.

### Статусы (выдаёт админ)
Профиль → **Админ-панель** → **Люди** → нажать на человека:

| Статус | Значок | Что даёт |
|---|---|---|
| Галочка | печать с галочкой | верифицированный пользователь |
| Щит | щит | модератор, открывается панель модератора |
| Молоток | молоток | статус разработчика |
| Админка | звезда | полный доступ к админ-панели |
| Снять все статусы | — | убирает всё сразу |

Там же — **Замутить** и **Заблокировать** с выбором срока и причины.

### Панель модератора
Появляется у того, кому выдали щит. Профиль → **Панель модератора**:
- **Публикации** — все посты, можно снять пост с причиной и наказать автора;
- **Жалобы** — жалобы людей друг на друга, с приложенными фото, можно наказать, закрыть или отклонить;
- **Мой статус** — сколько предупреждений накопилось.

### Контроль над модераторами
Админ-панель → **Наказания** — видно каждое действие модератора.
- **Отменить** — снимает наказание, снятый пост возвращается в ленту.
- **Отменить и предупредить** — то же самое плюс предупреждение модератору.
- На третьем предупреждении щит снимается автоматически, панель модератора закрывается.

Основателя `vanya8` нельзя забанить, замутить и лишить админки — это защищено на уровне базы.

## Приложение для Android

APK собирается автоматически при каждом изменении и лежит по постоянной ссылке:

**https://github.com/spokum/spokum/releases/download/apk/spokum-latest.apk**

Как поставить на телефон:

1. Открой ссылку в браузере телефона, скачай файл.
2. Нажми на скачанный файл. Android спросит разрешение ставить приложения из этого источника — разреши.
3. Появится иконка СпокУма.

Что внутри: весь интерфейс, шрифты и библиотека связи с базой лежат в самом приложении — оно не тянет ничего со сторонних сайтов, поэтому открывается мгновенно и одинаково выглядит без интернета. Данные берутся из той же базы Supabase, что и сайт, так что аккаунт и переписка общие.

Важно про обновления: после изменения сайта нужно дождаться новой сборки в Actions и установить новый APK. Сама Android-оболочка интерфейс с сайта не обновляет. При использовании постоянного ключа подписи новая версия ставится поверх старой.

Пересобрать вручную: вкладка **Actions** → слева **Build APK** → **Run workflow**.

## Если что-то не работает

**Не удаётся войти или зарегистрироваться** — проверь, что `https://api.spokum.ru/auth/v1/health` отвечает, а в конфигурации Auth на VDS разрешены регистрация и вход по email.

**Вверху ленты жёлтая плашка «Автономный режим»** — сайт не видит ключи. Проверь `web/config.js`: обе строки заполнены, коммит запушен, сборка в Actions прошла. Обнови страницу с Ctrl+F5.

**«Юзернейм занят»** — имя уже зарегистрировано, возьми другое.

**«Недостаточно прав»** — действие требует статуса, которого нет у аккаунта. Выдай статус через админ-панель.

**Нет интернета** — приложение и сайт покажут жёлтую полосу сверху и ленту, сохранённую с прошлого раза. Можно листать записи, открывать игры, менять темы. Публикация, чаты и жалобы вернутся вместе со связью.

**Лента пустая** — так и должно быть у новой сети. Никаких ботов и выдуманных людей здесь нет: появятся те, кто зарегистрируется.

**Пропали данные** — если плашка «Автономный режим» висела, всё писалось в браузер, а не в базу. Подключи Supabase и заведи аккаунт заново.

**Хочу почистить базу** — Supabase → SQL Editor → `truncate public.posts, public.messages, public.chats cascade;`

## Локальный запуск (по желанию)

```bash
cd web
python3 -m http.server 8080
```
Открыть http://localhost:8080. Ключи из `config.js` работают и локально.

В репозитории также лежит `server/` — старый бэкенд на Node и SQLite. Он не запущен и не используется текущим сайтом; для production нужен только Supabase на VDS.

## Что где лежит

```
web/            сайт: index.html, css/app.css, js/
web/config.js   ключи Supabase
supabase/       schema.sql, миграции и Edge Functions
infra/          скрипт ежедневного бэкапа и systemd unit/timer
server/         старый неиспользуемый бэкенд на Node + SQLite
.github/        публикация сайта и сборка приложений
```
